# 智能家居 3D 演练场 — 真实 Jev + OpenAI 语音版

参照官方智能家居教学视频的参考 UI 复刻的 3D 仿真屋：对它说话或打字，
一次 Jev 调用里塞进意图判断、复合检测、范围/设备定位和**全部五类设备的动作预判**（投机提示），
代码端按确定性分支剪枝，3D 场景实时执行。语音输入走 OpenAI 语音转写（`/v1/audio/transcriptions`，流式），
打字输入原样保留。

参考版（Downloads 里的 `typesafe_smart_home_3d_playground.html`）全部数据是写死的
关键词模拟器。本版把 Jev 真正接了进去：追踪面板里的每个概率、每毫秒延迟都是
API 真实返回、客户端实测的。

## 快速开始

```bash
cd smart-home
python3 serve_smart_home.py --port 8810     # 自动开浏览器

# 接真实 Jev（不设则页面自动用本地模拟引擎，功能一样，数据是模拟的）
export TYPESAFE_API_KEY=你的key              # console.typesafe.ai 获取

# 语音输入、复合拆分、知识问答、传统 LLM 对比走 OpenAI 官方 API，需要：
export OPENAI_API_KEY=你的key                # platform.openai.com 获取
# 可选：覆盖默认模型
# export OPENAI_ASR_MODEL=gpt-4o-mini-transcribe   # 或 whisper-1（非流式）
# export OPENAI_CHAT_MODEL=gpt-4o-mini             # 复合指令拆分
# export OPENAI_ANSWER_MODEL=gpt-4o-mini           # 知识问答
# export OPENAI_COMPARE_MODEL=gpt-4o               # 传统 LLM 对比
```

> 说明：本 demo 早期使用另一家托管 ASR/LLM 服务，现已整体替换为 OpenAI。
> 下文涉及旧服务的实测延迟/成本数字已删除，未用 OpenAI 重新测量；Jev 侧数字保持原样。

页面必须经这个本地服务打开（不能直接双击 HTML）：两个上游 API 不保证给浏览器
CORS 头，而且 key 也不能暴露在页面里，所以由它做代理。

## 语音怎么用

点输入框右侧的麦克风 → 说指令（中英文都行，自动检测）→ 再点一次结束
（或 ESC 取消，最长 15 秒自动停）→ 识别文字实时填进输入框 → 自动执行。
录音期间有红点脉冲、声浪条和计时。打字输入不受任何影响。

麦克风采集 16kHz 单声道 16-bit 裸 PCM（AudioWorklet，老浏览器自动退到
ScriptProcessor）。**说话过程中就在实时识别**：每新增约 1 秒音频，把已积累的
整段音频重识别一次（全量重识别保证文本前后一致、不切半词），文字边说边长出来；
停止后再做最终识别兜底。服务端把 16k PCM 封成 WAV，以 multipart 上传到
OpenAI `/v1/audio/transcriptions`（`stream=true`），把返回的
`transcript.text.delta` / `transcript.text.done` SSE 事件原样透传回页面；
`whisper-1` 不支持流式，服务端会把最终文本包装成同格式的单条 `done` 事件。
领域热词（客厅、咖啡机……）通过转写接口的 `prompt` 字段提示。

### 麦克风点不动/被拒绝？

浏览器对麦克风有三道门槛，页面会按实际原因给出对应提示：

1. **非安全上下文**（症状：用 `http://192.168.x.x` 局域网地址打开）：浏览器直接
   禁用麦克风。解决：`python3 serve_smart_home.py --host 0.0.0.0 --tls`，
   然后打开 `https://<本机IP>:8810`，对自签证书警告点「高级 → 继续前往」
   （服务首次会用 openssl 生成 `certs/` 下的证书）。
2. **权限被拒绝**：点地址栏左侧的锁/摄像头图标，把麦克风设为「允许」再重试。
3. **窗口不提供麦克风**：部分内嵌/小窗口浏览器不暴露 `getUserMedia`，
   换系统 Chrome/Safari 打开页面地址即可（`http://127.0.0.1` 本机地址在
   系统浏览器里测过可用）。

## 一次调用里发生了什么

和教程视频完全同款的投机提示结构，只是数据变成了真的：

1. **唯一的一次 Jev 调用**（`POST /v1/systemone`）捆绑 10 个问题：
   - `intent`（choice）：智能家居指令 / 信息请求 / 设备状态查询
   - `is_compound`（noul）：是否含多个独立操作
   - `scope` + `target_room` + `category`（choice）：范围 / 房间 / 设备类别
   - `light/fan/speaker/appliance/lock_action` 五个动作问题——**不管用户说什么都问**，
     无关的在代码端剪枝，相关的直接取用，零二次往返
2. 代码端按意图分支：
   - **信息请求** → 转交 OpenAI 问答模型（`OPENAI_ANSWER_MODEL`）回答
   - **状态查询** → 投机答案定位设备，状态从本地 3D 状态直读，零额外调用
   - **复合指令** → OpenAI 拆分模型（`OPENAI_CHAT_MODEL`）拆成原子子指令，每条并行再走一次 Jev
   - **单一指令** → 直接从投机答案取相关类别的动作和目标，派发到 3D

模型分工：拆指令与知识问答分别由 `OPENAI_CHAT_MODEL` / `OPENAI_ANSWER_MODEL`
配置（默认都是 `gpt-4o-mini`），可按需给问答换更强的模型——"按需分配算力"。

## 和传统 LLM 对比（OpenAI，默认 gpt-4o）

命令条左侧有管线切换：**Jev 投机 / 传统 LLM / 双路对比**。

- **传统 LLM**：同一段决策规则写成 JSON schema，让 `OPENAI_COMPARE_MODEL`（默认 `gpt-4o`）一次直答
  （意图、拆分、定位、动作、回答全在这一次输出里，拆分是它内联完成的——这是
  大模型的结构性优势，不需要编排）。页面把它的 JSON 转成与 Jev 完全相同的派发
  语义，追踪面板第 6 节显示其延迟、tokens 和原始输出。
- **双路对比**：同一指令同时发两路，第 1 节下方出现对照块——延迟、tokens、
  派发结果是否一致、LLM 慢几倍，一句话给结论。

Jev 输出免费、输入按 $0.042/M tokens 计，单次约合 $0.000017。传统 LLM 一侧的
延迟与成本请在页面里用自己的 `OPENAI_API_KEY` 实测（早期基于旧服务的对比数字已删除）。

## 串行 / 并行工作流编排（任务制）

复合指令不再一律并行。拆分之后多一次 Jev 编排调用，问两类问题（仍是单次往返）：

- 每对子指令一个 **noul**：「A 必须在 B 之前完成，B 才有意义/结果才正确吗？」
  ——同一设备动作相冲（先开后关同一盏灯）或存在因果前提 → 高概率；
  目标互不相关（厨房灯 + 书房门锁）→ 低概率。
- 每条子指令一个 **score**（0 最后 / 1 随时 / 2 最先，安全类优先）——用于同序位排序。

代码端规则：任一依赖概率 ≥ 60% → **串行执行栈**（按拓扑序 + 优先级逐个执行，
每个任务等前一个派发完才动，顺序决定最终状态）；全部低于阈值 → **并行**（原行为）。
追踪面板第 3 节下方实时显示依赖对、概率和执行栈状态（⏳/▶️/✅）。

实测（mock 上游）：「先把客厅灯打开，然后再把客厅灯关掉」→ 依赖 93% → 串行栈，
客厅灯最终为**关**（顺序保持）；「关掉厨房的灯，然后锁上书房的门」→ 无依赖 →
并行，且按优先级锁门排在关灯之前。编排分析本身只花 133–141ms。

## 踩过的坑

1. **ASR 的 `language` 字段**：只在明确给了语言时才带上；省略则由模型自动检测中英文。
2. **不走 MediaRecorder**，直接 AudioWorklet 采 16k 裸 PCM，服务端加 WAV 头再上传，
   格式最干净、跨浏览器一致。
3. **推理型模型的正文在 `reasoning_content`**，`content` 是空的——服务端做了回退。
4. **浏览器直连会被 CORS 拦 + key 不能进页面**，本地代理服务是必须的，不是可选。
5. 派发映射曾把返回属性写成 `dispatched`、消费端读 `dispatchedActions`，
   `Object.assign` 对 undefined 静默吞掉——表现为“追踪面板全对、设备纹丝不动”。
   一次改名修掉。教训：这种“显示层正确、副作用丢失”的 bug，要盯数据流而不是 UI。

## 已知边界

- 语音只能在 `http://127.0.0.1`（或 https）下用——浏览器的 getUserMedia 安全上下文要求；
  本地服务默认就满足。
- 说话人音量太小或环境噪杂时 ASR 可能返回空文本，页面会提示“没听清”，再试即可。
- `smart_home_query` 的设备定位依赖投机答案的 `category + target_room`，
  问法太模糊（“家里现在什么情况”）会退化为全屋状态摘要。
